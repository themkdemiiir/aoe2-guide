# scripts/data-pipeline — VM-side data ingestion + replay analysis

This directory is the **VM-side data workload**, NOT part of the Cloudflare Pages
static build. Nothing here runs during `pnpm build`; it runs out-of-band on the
data VM and produces committed inputs that the site (and the analyzer) read.

What lives here:

- **Relic / aoestats crawl + ingestion** — `collect-relic.mjs`, `stream-relic.mjs`,
  `ingest-stream.mjs`, and the `aggregate-*` / `refresh-*` generators.
- **DuckDB SQL** — `build-duckdb.sql`, `build-match-ages.sql`, `build-benchmark.sql`,
  `load-replays.sql`, run against the VM's `aoe2.duckdb`.
- **`replay-rs/`** — the Rust replay crate (bulk download+parse pipeline and the
  `analyze` game-coach subcommand).

Outputs are **committed inputs** consumed at build/run time, not regenerated by CI:

- `src/data/*.json` — civ/map/matchup stats the Astro pages render.
- `public/civ-cube.json` — the cube the client-side stat filters slice.
- `replay-rs/data/*` (`benchmark.json`, `costs.json`, `maps.tsv`, `civs.tsv`) —
  baked into the `replay-rs` binary via `include_str!`.

**Ingestion boundary:** `lib/buckets.mjs` is the single source for ELO bucketing
(`eloBucket` / `eloCaseSql`) and map canonicalization (`canonMap`). Every JS
generator imports it; the paired `.sql` files mirror the same thresholds inline —
keep the two faces in sync.

## The three crawl-record gates (2026-07 correctness fix)

Every consumer of crawl NDJSON goes through `lib/relic-map.mjs` +
`lib/crawl-stream.mjs`, which enforce, in order:

1. **Ranked RM only** — the record's `ladder` field is Relic's `matchtype_id`;
   only 6 (1v1 RM) and 7/8/9 (team RM) count. The crawl also captures Empire
   Wars, DM, quickplay, and event AUTOMATCH games — those must never enter RM
   stats.
2. **Current id-space era only** — the API's `civilization_id` is **Relic's own
   civ enumeration** (NOT the game/replay `civ_id` space) and it RE-SHUFFLES at
   some DLC/patch boundaries. `src/data/relic-civ-id-map.json` (provenance
   inside) is only valid from its `validFrom` (2025-09-01); older matches are
   excluded rather than mislabeled.
3. **Fail-loud civ mapping** — `relicCivSlug()` throws on an unknown id (a new
   DLC shifting the table must break the regen, not silently vanish).

**Maps:** the API's per-match `mapname` is wrong for ~57% of matches (measured
against 133k replay-parsed matches). Per-match map truth comes ONLY from the
replay pipeline's `data-cache/replays/shards/meta.ndjson.gz`
(`loadReplayMapTruth()`); matches without a parsed replay contribute no map
slice. `sweep.sh` keeps that shard current by downloading+parsing a capped
batch of fresh replays every cycle.

## Full regen chain (run on the VM, in this order)

```bash
node scripts/migrations/2026-07-02-rebuild-crawl-rows.mjs   # once (DuckDB crawl rows)
node scripts/data-pipeline/aggregate-rich.mjs        # frozen aoestats civ baseline
node scripts/data-pipeline/aggregate-maps.mjs        # frozen aoestats map baseline
node scripts/data-pipeline/refresh-civ-current.mjs   # live 1v1 overlay
node scripts/data-pipeline/refresh-team-current.mjs  # live team overlay
node scripts/data-pipeline/refresh-map-current.mjs   # live per-map 1v1 (replay-verified)
node scripts/data-pipeline/refresh-matchups-current.mjs
node scripts/data-pipeline/aggregate-patches.mjs     # monthly byPatch axis
node scripts/data-pipeline/build-civ-cube.mjs        # civ×elo×map×month cube
```

Then rsync `src/data/*.json` + `public/civ-cube.json` back and run
`pnpm validate:stats && pnpm build` locally.
